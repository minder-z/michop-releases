## これは何をするもの？

私は普段 MacBook で仕事をしつつ、リモートデスクトップソフト（UU Remote、Sunlogin、ToDesk など）で Mac mini に接続して作業しています。たとえば Claude Code にコードを書かせたり、動画を編集したり、Web サイトを管理したりです。

困るのは、**Mac mini にはマイクがなく、リモートデスクトップソフトも MacBook のマイクを転送してくれない**ことです。そのため、リモートデスクトップの中では音声入力が使えません。

MicHop はこの問題を解決します。2 台のパソコンにそれぞれ 1 つずつインストールします。

- **話す側のパソコン**（例：MacBook）：「MicHop」をインストール
- **作業する側のパソコン**（例：Mac mini）：「MicHop Receiver」をインストール

```
MacBook（話す側）                            Mac mini（作業する側）

マイク ──── 🔊 音声 ──────────────►  仮想マイク（内蔵の MicHop Audio）
                                      → 音声入力 / WeChat 入力法 / Claude Code の音声モード

              LAN または Tailscale 経由
```

MacBook のマイクの音声がリアルタイムで Mac mini に届き、Mac mini のマイクとして使えるようになります。macOS の音声入力、WeChat 入力法の音声入力、Claude Code の音声モードなど、Mac mini でマイクを使うアプリならどれでも利用できます。

- 受信側には仮想オーディオデバイス **MicHop Audio** が内蔵されていて、初めて開いたときにインストールを案内します（管理者パスワードの入力が 1 回必要です）。別途ダウンロードする必要はありません。[BlackHole](https://github.com/ExistentialAudio/BlackHole) をすでにインストールしている場合は、そのまま使い続けられます。
- 話し方は 2 通りあり、どちらもいつでも使えます。**⌃⌥M** を 1 回押すと送信し続け、もう一度押すと止まります。または **⌃⌥ を押している間**だけ話し、離すと止まります。
- エコーキャンセルを内蔵しているので、リモートデスクトップで接続中でもエコーが起きません。
- リモートデスクトップソフトでは Fn キーが届かないため、Mac mini 側の音声入力ショートカットを Ctrl + Option などの修飾キーの組み合わせに変えておきましょう。[詳しくは後述](#ヒントリモート接続では-fn-キーが届かないのでショートカットを変える)。

### 2 台のパソコンをつなぐ方法

- **同じ LAN にいる場合**：Mac mini の LAN の IP を入力するだけです。
- **離れた場所にある場合**：両方のパソコンに [Tailscale](https://tailscale.com) をインストールして仮想 LAN を作り、Mac mini の **Tailscale の IP**（100 で始まる）を入力します。自宅でも外出先でも同じように使えます。
- 受信側のウインドウには LAN の IP、Tailscale の IP、パスコードが表示され、それぞれの横にコピーボタンがあります。

### その他の特長

- **クラウドサービスを一切経由しない**：音声はご自身の 2 台のパソコンの間だけで直接やり取りされ、通信は最初から最後まで暗号化されます。経路は LAN か Tailscale です。
- **リモートデスクトップソフトを選ばない**：UU Remote、Sunlogin、ToDesk、画面共有のいずれとも組み合わせて使えます。
- **自動アップデート**：新しいバージョンが出ると自動で更新され、権限を許可し直す必要もありません。
- **多言語対応**：简体中文、繁體中文、English、日本語、한국어、Español、Français、Deutsch、Português、Русский に対応しています。初期設定は簡体字中国語で、「設定… → 一般 → 言語 / Language」で切り替えられます。

## ダウンロードとインストール

[Releases](../../releases/latest) からダウンロードします。

| ファイル | インストールするパソコン | メニューバーのアイコン |
|---|---|---|
| `MicHop.zip`（MicHop） | 話す側のパソコン（例：MacBook） | アプリのアイコンと同じ 2 本のマイク |
| `MicHop-Receiver.zip`（MicHop Receiver） | 作業する側のパソコン（例：Mac mini） | 同上 |

メニューバーのアイコンの色で状態がわかります。**グレー**＝未接続、**緑**＝接続中、**赤**＝音声を送信中です。

> **どちらのアプリもメインウインドウが中心です**：Dock のアイコンをクリックするとメインウインドウが開きます。上部には「接続状態」（グレー / 青）と「音声」（グレー / 赤）の 2 つの状態が表示され、よく使う操作はすべてウインドウ内にあります。ショートカット、言語、自動アップデートなどは「設定…」（⌘,）にまとめてあります。メニューバーのアイコンと Dock アイコンの右クリックメニューには、よく使う項目だけを残しています。MacBook のカメラ（ノッチ）でメニューバーのアイコンが隠れてしまう場合は、Dock のアイコンを使ってください。

macOS 13 以降が必要です。Apple シリコンと Intel プロセッサのどちらの Mac でも動作します。

> **初回起動時に「開発元を検証できません」と表示される場合**：このアプリは Apple の有料の公証を受けていないためです。システム設定 → プライバシーとセキュリティ を開き、ページ下部の「このまま開く」をクリックしてください。または、ターミナルで次のコマンドを実行して隔離属性を解除してから開くこともできます。
> ```bash
> xattr -dr com.apple.quarantine "/Applications/MicHop Receiver.app"
> ```

### 1. 作業する側のパソコン（受信側）

1. `MicHop-Receiver.zip` を展開し、「MicHop Receiver」を「アプリケーション」フォルダにドラッグしてから開きます。
   - 「ネットワーク受信接続を許可しますか？」と表示されたら、**許可**をクリックします。
2. 初めて開くと、内蔵の仮想オーディオデバイス **MicHop Audio** のインストールを案内されます。「インストール」をクリックして管理者パスワードを 1 回入力してください。インストールが終わるとき、システムの音声が 1〜2 秒途切れます。あとから「設定… → 仮想オーディオデバイス」でインストールすることもできます。
3. インストールが済んだら、案内に従って**システムの入力装置**を MicHop Audio に変更します（メインウインドウの「準備状況」にも「変更する」ボタンがあります）。システムの**出力**装置はスピーカー（またはリモートデスクトップソフトのオーディオデバイス）のままで構いません。MicHop Audio はシステムの出力には選べないので、システムの音が混ざることはありません。
4. メインウインドウには次の情報が表示されます。
   - **接続情報**：この Mac の LAN アドレス、Tailscale アドレス、パスコード。それぞれの横にコピーボタンがあります。
   - **準備状況**：仮想オーディオデバイスとシステムの入力装置の両方に緑のチェックマークが付けば準備完了です。黄色の警告が出ている項目は、右側にそのまま修正用のボタンが表示されます。
5. 初期設定ではログイン時に自動で起動します。不要な場合は「設定… → 一般」でオフにできます。

> **BlackHole をすでに使っている場合**：そのまま使えます。「準備状況 → 音声の出力先」で使いたいデバイスを選んでください。内蔵のデバイスに切り替えたい場合は、「内蔵の仮想デバイスに切り替えられます」の横にある「インストール」をクリックします。BlackHole を使うときは、システムの出力に選ばないよう注意してください。誤って選ぶと「準備状況」に「システムの出力」の警告が表示されるので、「スピーカーに戻す」をクリックすれば元に戻ります。

### 2. 話す側のパソコン（送信側）

1. `MicHop.zip` を展開し、「MicHop」を「アプリケーション」フォルダにドラッグしてから開きます。
2. 初めて開くと設定ウインドウが表示されます。受信側の**アドレス**と**パスコード**を入力して「接続をテスト」をクリックし、緑色の「接続しました。使えます」が表示されたら「保存」をクリックします。
   - 受信側のウインドウでは、アドレスとパスコードの横にあるコピーボタンで、それぞれを個別にコピーできます。
   - 受信側で「すべてコピー」をクリックし、まとめて「アドレス」欄に貼り付けることもできます。送信側がアドレスを自動で取り出し（Tailscale アドレスがあればそちらを優先）、パスコードも自動で入力します。
   - 「ローカルネットワーク上のデバイスの検索および接続」の許可を求められたら、**許可**をクリックします。
3. 初回は**マイク**へのアクセスを求められるので、許可してください。また、**アクセシビリティ**の権限（「⌃⌥ を押している間」の検出に使います）も求められるので、案内に従って システム設定 → プライバシーとセキュリティ → アクセシビリティ で「MicHop」をオンにします。
4. アプリを開くと受信側に接続します。メインウインドウの「接続状態」が青になり、メニューバーのアイコンが緑になれば使えます。あとでアドレスやパスコードを変更するには、メインウインドウの「受信側」の欄にある「変更…」をクリックするか、⌘, を押します。

## 使い方

まずリモートデスクトップ上で、作業する側のパソコンの音声を使いたい場所をクリックします。たとえば Claude Code の音声モード、macOS の音声入力、入力方式などです。あとは 2 通りの話し方をいつでも使えます。

1. **送信し続ける**：**⌃⌥M（Ctrl + Option + M）**を 1 回押すか、メインウインドウの「音声送信を開始」をクリックすると、マイクがオンのままになります。もう一度押すと止まります。
2. **押している間だけ送信する**：**Ctrl + Option を押したまま話し、離すと止まります**。キーを押している間だけマイクがオンになります。

送信中は、メインウインドウの「音声」とメニューバーのアイコンが赤になります。受信側の「音声」も赤になります。

- 押しているキーは、リモートデスクトップソフトによって作業する側のパソコンにも送られます。そちらのパソコンで音声入力や入力方式の音声ショートカットも Ctrl + Option に設定しておけば（[下のヒント](#ヒントリモート接続では-fn-キーが届かないのでショートカットを変える)を参照）、**1 回押すだけで「音声の送信」と「向こう側での音声入力の開始」を同時に行えます**。
- キーを押して話している間、MicHop はこの Mac の音を一時的にミュートします。相手側のパソコンの音がリモートデスクトップソフト経由で戻ってきて、マイクに拾われてエコーになるのを防ぐためです。キーを離してから約 1 秒後に自動で元に戻ります（「送信し続ける」場合は Apple のエコーキャンセルを使います）。

> **ショートカットは変更できます**：「設定… → ショートカット」でボタンをクリックし、新しいキーの組み合わせを押してください。「送信開始」には ⌃、⌥、⌘ のいずれかを含む組み合わせを、「押して話す」には ⌃ ⌥ ⇧ ⌘ のうち 2 つ以上の組み合わせを使えます。選んだ組み合わせがすでにシステムで使われている場合（たとえば ⌃⌥スペース は多くの Mac で「入力メニューの次のソースを選択」に割り当てられています）、アプリにオレンジ色の案内が表示されます。システム設定 → キーボード → キーボードショートカット でその項目をオフにするか、別の組み合わせに変えてください。

> **なぜエコーが起きるのか？** 多くのリモートデスクトップソフト（UU Remote など）は、Apple の画面収録フレームワークを使って操作される側のパソコンの音声を取り込んでいます。このとき、どのオーディオデバイスに出力されているかに関係なく、そのパソコンの**すべてのアプリの音**が収録されます。そのため、MicHop があなたの声を仮想オーディオデバイスに流すと、その声も一緒に収録されてあなたのパソコンに送り返され、スピーカーから再生されて、またマイクに拾われてしまいます。
>
> そこで送信側では、**エコーキャンセル**が初期設定でオンになっています（メインウインドウの「オプション」でオフにできます）。FaceTime と同じ Apple の音声処理を使い、戻ってきた音声をマイクの信号から差し引き、話している間はほかの音を小さくし、あわせてノイズも抑えます。ヘッドフォンを使うと最も効果的です。

### ヒント：リモート接続では Fn キーが届かないので、ショートカットを変える

UU Remote、Sunlogin、ToDesk などのリモートデスクトップソフトで接続しているときは、**手元の Mac で Fn キーを押しても、操作される側には届きません**。操作される側で macOS の音声入力を使っていても、WeChat 入力法の音声入力を使っていても、起動できません。理由は 2 つあります。Fn キーはまず手元の Mac に横取りされる（手元の Mac で音声入力が始まってしまう）こと、そしてリモートデスクトップソフトが転送したとしても、操作される側では「仮想的なキー入力」として扱われ、システムや入力方式がたいてい反応しないことです。

解決方法：**操作される側**（例：Mac mini）で、音声入力のショートカットを変更します。

- **macOS の音声入力**：システム設定 → キーボード → 音声入力 → ショートカット →「カスタマイズ」。
- **WeChat 入力法**：WeChat 入力法の設定で、音声入力のショートカットを変更します。

おすすめは**修飾キーの組み合わせ**です。たとえば**左側の Ctrl + Option**、または Ctrl とほかの修飾キー（Option、Shift、Command）の組み合わせです。

**Ctrl と数字キーや文字キーの組み合わせ（Ctrl+D など）は避けてください**。音声入力はたいていキーを押したまま話すので、文字キーや数字キーを押し続けるとその文字が繰り返し入力されてしまい、とても使いにくくなります。修飾キーだけの組み合わせなら、押し続けても文字は入力されません。

操作される側の入力装置を MicHop Audio にしておけば、リモートデスクトップ上で新しいショートカットを押したまま話すだけで、操作される側で直接音声入力できます。

## Mac mini の音を手元に返す（仮想スピーカー）

受信側に付属の仮想オーディオデバイスには、**仮想スピーカー MicHop Speaker** も入っています（1.6.0 以降）。あなたのマイクの音を流す MicHop Audio とは別々のデバイスなので、音が混ざることはありません。

受信側の「設定… → 仮想オーディオデバイス」で「このMacの音声を MicHop Speaker に出力」をオンにすると：

- Mac mini のシステム出力が MicHop Speaker に切り替わり、**本体のスピーカーからは音が出ません**。部屋で突然音が鳴ることもありません。
- オーディオデバイスを選べるリモートデスクトップソフトや画面収録ソフト（Sunlogin、ToDesk の一部のバージョン、OBS など）では、MicHop Speaker を音声ソースに選ぶと、Mac mini の音を手元に返せます。
- キーボードの音量キーもそのまま使え、収録される音は音量に合わせて変わります。
- スイッチをオフにしたとき、受信側を終了したとき、仮想オーディオデバイスをアンインストールしたときは、システム出力が自動で元のデバイスに戻ります。

> UU Remote のように Apple の画面収録で音声を取り込むリモートデスクトップソフトは、音がどのデバイスに出力されていても収録できます。そのため、これらのソフトにとって仮想スピーカーの主な利点は「Mac mini 本体のスピーカーは鳴らないのに、リモート側ではちゃんと聞こえる」ことです。

受信側のメインウインドウの「準備状況」の最後の行「このMacの音声」に、このパソコンの音がいまどこに出力されているかが表示されます。

## 同じネットワークにいない？ Tailscale を使う

1. 両方のパソコンに [Tailscale](https://tailscale.com) をインストールし、同じアカウントでログインします。
2. 受信側のメインウインドウの「接続情報」にある「Tailscale」の行に 100.x.x.x が表示されるので、それを送信側の設定に入力します。Tailscale に表示されるマシン名を入力することもできます。
3. 「見つかりません」と表示される場合は、まず受信側のパソコンで Tailscale が接続されていることを確認し、その行の更新ボタンをクリックして再検出してください。それでも検出できない場合は、受信側の「設定… → Tailscale → アドレスを手動設定」に、Tailscale のメニューに表示されているアドレスを入力します。

Tailscale のアドレスは自宅でも外出先でも使えます。2 台が同じ LAN にあるときは、自動的に直接接続されます。

## セキュリティ

- **音声は最初から最後まで暗号化されます**：接続のたびにまず鍵交換（X25519）を行い、その後の音声はすべて ChaCha20-Poly1305 で暗号化されます。同じネットワーク内で盗み聞きやパケットキャプチャをする人に対しては、話している内容も、パスコードも知られません。パスコード自体がネットワーク上に送られることはありません。
- 受信側にはそれぞれランダムな 6 桁のパスコードがあり、パスコードが正しくない接続はすべて拒否されます。5 回続けて間違えると、受信側は 30 秒間新しい接続を受け付けず、メインウインドウに「誰かがパスコードを試しています」と表示されます。受信側のメインウインドウの「パスコード」の行で「新しくする」をクリックすると変更できます（変更後は送信側で入力し直す必要があります）。
- **防げないもの**：接続を能動的に乗っ取り、受信側になりすます人。6 桁のパスコードは 100 万通りしかないため、ハンドシェイクを 1 回手に入れればオフラインで総当たりできてしまいます。そのため、自宅のネットワークか Tailscale の中だけで使い、受信側のポート（TCP **8766**）をインターネットに公開しないでください。
- 送信側と受信側は、どちらも 1.6.0 以降のバージョンである必要があります。片方が古すぎると、もう片方に「バージョンが古すぎます」と表示されるので、アップデートしてください。

## よくある質問

- **接続できない**：2 台のパソコンが同じネットワークにあるか、両方とも Tailscale に接続しているかを確認してください。LAN の IP は変わることがあるので、ルーターで受信側に固定 IP を割り当てるか、Tailscale のアドレスを使うことをおすすめします。
- **受信側に「ポートを開けない」と表示される**：たいていは古い受信側が完全に終了しておらず、ポートを使ったままになっています。受信側が自動で終了させます。ほかのアプリが使っている場合は案内にそのアプリ名が表示され、ポートが解放されると受信側が自動で起動します。
- **⌃⌥ を押しても反応しない**：送信側には**アクセシビリティ**の権限が必要です。アプリをビルドし直したりアップデートしたりすると、macOS が以前の許可を無効にすることがあります。アクセシビリティの一覧から古い項目を削除してから、改めて追加してください。

## 自動アップデート

どちらのアプリも GitHub で新しいバージョンを自動で確認します。起動の 30 秒後に 1 回、その後は 6 時間ごとに確認します。新しいバージョンが見つかると、自動でダウンロードして置き換え、開き直します。

- 現在のバージョン番号はメインウインドウの左下に表示されます。「設定… → 一般」で「アップデートを確認」をクリックすると、すぐに確認できます。
- 自動でインストールしたくない場合は、「設定… → 一般」で「アップデートを自動でインストール」をオフにします。その後は新しいバージョンが出ると、設定に「x.y.z にアップデート」ボタンが、メニューバーのメニューにも同じ項目が表示され、クリックしたときだけアップデートされます。
- 使用中に邪魔をすることはありません。音声の送信中はアップデートしません。
- セキュリティ：新しいバージョンが現在のバージョンと**同じ証明書**で署名されていない場合、インストールを拒否します。
- アップデート後も、アクセシビリティやマイクなどの権限はそのまま残るので、許可し直す必要はありません。
