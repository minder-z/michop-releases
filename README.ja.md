## これは何のためのもの？

私は普段 MacBook で仕事をしていて、リモートデスクトップソフト（UU Remote、Sunlogin、ToDesk など）で Mac mini に接続して作業しています。たとえば Claude Code にコードを書かせたり、動画を編集したり、Web サイトを管理したり。

困るのは、**Mac mini にはマイクがなく、リモートデスクトップソフトも MacBook のマイクを転送してくれない**ことです。そのため、リモートデスクトップ上では音声入力ができません。

MicHop はまさにこの問題を解決します。2 台のパソコンにそれぞれ 1 つずつインストールします：

- **話す側のパソコン**（例：MacBook）：「MicHop」をインストール
- **作業する側のパソコン**（例：Mac mini）：「MicHop Receiver」をインストール

### 2 つの送り方、メインウインドウからいつでも切り替え

```
MacBook（話す側）                            Mac mini（作業する側）

マイク ──── 🔊 音声を送信 ─────────►  仮想マイク（内蔵の MicHop Audio）
                                      → 音声入力 / WeChat Input Method / Claude Code ボイスモード

音声入力 ── 📝 テキストを送信 ──────►  カーソル位置にペースト、自動で Return も可

              LAN または Tailscale 経由
```

**🔊 音声を送信：Mac mini があなたの声を直接「聞く」**

MacBook のマイクの音声がリアルタイムで Mac mini に送られ、Mac mini のマイクになります。Mac mini 上でマイクを使うアプリならどれでも利用できます。たとえば macOS の音声入力、WeChat Input Method の音声入力、Claude Code のボイスモードなど。

- Receiver には仮想オーディオデバイス **MicHop Audio** が内蔵されています。初めて音声を送るときにインストールを案内され（管理者パスワードの入力が 1 回必要です）、別途ダウンロードする必要はありません。以前 [BlackHole](https://github.com/ExistentialAudio/BlackHole) をインストールした方は、そのまま使い続けることもできます。
- エコーキャンセル機能を内蔵しているので、リモートデスクトップソフトで接続していてもエコーは発生しません。
- リモートデスクトップソフトでは Fn キーが届かないので、音声入力のショートカットを Ctrl + Option などの修飾キーの組み合わせに変更してください。[詳しくは後述](#ヒントリモート接続では-fn-キーが届かないのでショートカットを変更する)。

**📝 テキストを送信：MacBook で認識して、文字を送る**

MacBook で ⌃⌥Space（Ctrl + Option + Space）を押し、macOS の音声入力で話した内容をテキストにします。それを Mac mini に送ると、カーソル位置に自動でペーストされます。さらに自動で Return を押して、そのまま Claude に送信することもできます。

- Mac mini にオーディオドライバを入れる必要も、オーディオ設定をする必要もありません。いちばん手軽で、いちばん安定しています。
- アプリのデフォルトはこのモードです。

| | 🔊 音声を送信 | 📝 テキストを送信 |
|---|---|---|
| どちらのパソコンで認識するか | Mac mini（そのマシンの音声入力や IME を使用） | MacBook（macOS の音声入力を使用） |
| Mac mini に必要なもの | Receiver + 内蔵の仮想オーディオデバイス（初回使用時にインストール） | Receiver のみ |
| 向いている用途 | Mac mini 上の IME・音声入力・Claude ボイスモードを使いたい | 話した言葉を文字にして入力したいだけ |

### 2 台のパソコンの接続方法

- **同じ LAN 内にある場合**：Mac mini の LAN IP を入力するだけです。
- **離れた場所にある場合**：2 台とも [Tailscale](https://tailscale.com) をインストールして仮想 LAN を組み、Mac mini の **Tailscale IP**（100 で始まる）を入力します。**音声もテキストも Tailscale 経由で送れる**ので、自宅でも外出先でも同じように使えます。
- Receiver のウインドウには LAN IP、Tailscale IP、パスコードが表示され、それぞれの横にコピーボタンがあります。

### その他の特長

- **クラウドサービスを一切経由しない**：音声もテキストも、あなた自身の 2 台のパソコンの間で直接やり取りされます。経路は LAN か、Tailscale の暗号化トンネルです。
- **リモートデスクトップソフトに依存しない**：UU Remote、Sunlogin、ToDesk、画面共有のいずれとも併用できます。
- **自動アップデート**：新しいバージョンが出ると自動で更新され、権限を付与し直す必要もありません。
- **多言語対応**：インターフェースは 简体中文、繁體中文、English、日本語、한국어、Español、Français、Deutsch、Português、Русский に対応しています。デフォルトは中国語で、「設定… → 一般 → 言語 / Language」から切り替えられます。

## ダウンロードとインストール

[Releases](../../releases/latest) からダウンロードします：

| ファイル | インストール先 | メニューバーのアイコン |
|---|---|---|
| `MicHop.zip`（MicHop） | 話す側のパソコン（例：MacBook） | アプリアイコンと同じ角丸の四角 |
| `MicHop-Receiver.zip`（MicHop Receiver） | 作業する側のパソコン（例：Mac mini） | 同上 |

メニューバーのアイコンの色で状態がわかります：**グレー**＝未接続、**緑**＝接続済み、**赤**＝送信中（話している / 音声を受信中）。

> **どちらのアプリもメインウインドウが中心です**：Dock アイコンをクリックするとメインウインドウが開き、上部の 2 つの枠に状態が表示されます：「接続状態」（グレー / 青）と「音声」（グレー / 赤）。よく使う操作はすべてウインドウにあり、言語や自動アップデートなどは「設定…」（⌘,）にまとめています。メニューバーのアイコンと Dock アイコンの右クリックメニューには、よく使う項目だけを残しています。MacBook のカメラ（ノッチ）でメニューバーのアイコンが隠れるときは、Dock アイコンを使ってください。

macOS 13 以降が必要です。Apple シリコンと Intel のどちらの Mac でも動作します。

> **初回起動時に「開発元を検証できません」と表示される場合**：これはこのアプリが有料の Apple 公証を受けていないためです。システム設定 → プライバシーとセキュリティ を開き、ページ下部の「このまま開く」をクリックしてください。または、ターミナルで次のコマンドを実行して隔離属性を解除してから開くこともできます：
> ```bash
> xattr -dr com.apple.quarantine "/Applications/MicHop Receiver.app"
> ```

### 1. 作業する側のパソコン（Receiver）

1. `MicHop-Receiver.zip` を展開し、「MicHop Receiver」を「アプリケーション」にドラッグして開きます。
2. 案内に従って**アクセシビリティ**の権限をオンにします：システム設定 → プライバシーとセキュリティ → アクセシビリティ →「MicHop Receiver」をオン。あなたの代わりに ⌘V を押すために、この権限が必要です。
   - 「受信ネットワーク接続を受け入れますか？」と表示されたら、**許可**をクリックします。
3. Dock の「MicHop Receiver」アイコンをクリックすると、メインウインドウに次の内容が表示されます：
   - **接続情報**：このマシンの LAN アドレス、Tailscale アドレス、パスコード。それぞれの横にコピーボタンがあります。
   - **準備状況**：「アクセシビリティの許可」の行が緑のチェックマークになっているはずです。黄色の警告が出ている項目には、右側に修正用のボタンが表示されます。
4. 「ログイン時に起動」がデフォルトでオンになっています。不要なら「設定… → 一般」でオフにできます。

### 2. 話す側のパソコン（送信側）

1. `MicHop.zip` を展開し、「MicHop」を「アプリケーション」にドラッグして開きます。
2. 初めて開くと設定ウインドウが表示されます。Receiver の**アドレス**と**パスコード**を入力し、「接続をテスト」をクリックします。緑色で「接続しました。使えます」と表示されたら「保存」をクリックします。
   - Receiver のウインドウでは、アドレスやパスコードの横にあるコピーボタンで、それぞれ個別にコピーできます。
   - Receiver で「すべてコピー」をクリックし、丸ごと「受信側アドレス」欄にペーストすることもできます。送信側が自動でアドレスを選び出し（Tailscale アドレスがあればそちらを優先）、パスコードも自動で入力されます。
   - 「ローカルネットワーク上のデバイスの検出を許可しますか？」と表示されたら、**許可**をクリックします。
3. macOS の音声入力がオンになっていることを確認します：システム設定 → キーボード → 音声入力。
4. メインウインドウの上部に「受信側に接続しました」と表示されたら使えます。あとでアドレスやパスコードを変えたいときは、メインウインドウの「受信側」欄にある「変更…」をクリックするか、⌘, を押します。

## 使い方

1. まずリモートデスクトップ上で、作業する側のパソコンの入力欄（Claude Code など）をクリックします。
2. **⌃⌥Space（Ctrl + Option + Space）** を押すと、画面下部に小さなウインドウが表示され、自動で音声入力が始まります。自動で始まらない場合は、Fn を 1 回押してください。
3. 話し終えたら **Return** を押すと、もう一方のパソコンにテキストが表示されます。

| キー | 動作 |
|---|---|
| Return / もう一度 ⌃⌥Space | 送信 |
| Shift + Return | 改行 |
| Esc | キャンセル |

小さなウインドウの上部には、テキストの送信先のパソコンが表示されます。左下には「送信後に自動でReturn」というオプションがあり、デフォルトでオンになっています。テキストはそのまま Claude に送信されます。一度確認してから手動で送信したい場合は、チェックを外してください（メインウインドウの「オプション」にも同じスイッチがあります）。

リモートデスクトップソフトがこのキーの組み合わせを横取りしてしまい、小さなウインドウが表示されない場合は、メインウインドウの大きな「話す」ボタンをクリックするか、メニューバーのアイコン →「話す」をクリックしてください。

> **ショートカットは変更できます**：「設定… → ショートカット」でボタンをクリックし、新しいキーの組み合わせを押します。Mac によっては、⌃⌥Space がすでにシステムの「入力メニューの次のソースを選択」に割り当てられていて、押すと入力ソースが切り替わってしまいます。その場合はアプリにオレンジ色の案内が表示されます：システム設定 → キーボード → キーボードショートカット → 入力ソース でその項目をオフにするか、MicHop で別のキーの組み合わせに変更してください。

## 2 つの送信モード

メインウインドウの「送信方法」で「文字」または「音声」のカードをクリックして切り替えます。メニューバーのアイコンのメニューからも切り替えられます。**デフォルトはテキスト送信です。**

| | テキストを送信（デフォルト） | 音声を送信 |
|---|---|---|
| どこで認識するか | このマシンで macOS の音声入力によりテキスト化 | 相手のパソコンで、そのマシンの音声入力や Claude Code ボイスモードで認識 |
| ⌃⌥Space の役割 | 音声入力の小ウインドウを表示 | 「常に送信」の開始・停止 |
| ⌃⌥ を押したまま | — | 押している間だけ送信、離すと停止 |
| メインウインドウの大きなボタン | 「話す」 | 「音声送信を開始」/「音声送信を停止」 |
| 相手側に必要なもの | Receiver のみ | Receiver と内蔵の仮想オーディオデバイス |

## 音声送信モード

作業する側のパソコンに**あなたの声を直接聞かせたい**ときに使うモードです。たとえば、そのパソコン上の Claude Code のボイスモードや、そのマシン自身の音声入力を使う場合です。

```
MacBook のマイク ──音声──► Receiver ──► 仮想オーディオデバイス MicHop Audio ──► そのマシンで「マイクを聞く」あらゆるアプリ
```

**Receiver 側のパソコンで事前に準備すること：**

1. 内蔵の仮想オーディオデバイス **MicHop Audio** をインストールします：送信側から初めて音声を送ると、Receiver に案内が表示されるので「インストール」をクリックします。Receiver の「設定… → 仮想オーディオデバイス」で「インストール」をクリックすることもできます。管理者パスワードの入力を 1 回求められ、インストール後にシステムの音声が 1〜2 秒途切れます。
2. インストールが終わったら、案内に従って**システムの入力デバイス**を MicHop Audio に変更します（メインウインドウの「準備状況」にも「変更する」ボタンがあります）。
3. システムの**出力**デバイスはスピーカー（またはリモートデスクトップソフトのオーディオデバイス）のままにします。MicHop Audio はそもそもシステムの出力として選べないので、システムの音が混ざることはありません。

> **以前 BlackHole をインストールした場合は？** そのまま使えます：「準備状況 → 音声の出力先」で使いたいデバイスを選んでください。内蔵のものに切り替えたいときは、「内蔵の仮想デバイスに切り替えられます」の横にある「インストール」をクリックします。BlackHole を使う場合は、システムの出力に選ばないよう注意してください。間違えて選んだ場合は「準備状況」に「システムの出力」の警告が出るので、「スピーカーに戻す」をクリックしてください。

> **なぜエコーが起きるのか？** 多くのリモートデスクトップソフト（UU Remote など）は、Apple の画面収録フレームワークを使って操作される側のパソコンの音声を取り込みます。このとき、どのオーディオデバイスに出力されているかに関係なく、そのパソコン上の**すべてのアプリの音**が録音されます。MicHop があなたの声を仮想オーディオデバイスに流すと、それも一緒に録音されてあなたのパソコンに送り返され、スピーカーから再生され、それをまたマイクが拾ってしまいます。
>
> そのため送信側では、デフォルトで**「エコーキャンセル」**がオンになっています（メインウインドウの「オプション」からオフにできます）。これは FaceTime でも使われている Apple の音声処理です：送り返されてきた音をマイクの信号から差し引き、あなたが話している間はほかの音を抑え、ついでにノイズも低減します。ヘッドホンを使うと最も効果的です。

**使い方：**

メインウインドウの「送信方法」で「音声」を選ぶと、送信側が Receiver に接続し（初回はマイクへのアクセス許可を求められます）、「接続状態」が青に、メニューバーのアイコンが緑になります。そのあとは、2 つの話し方をいつでも使えます：

1. **常に送信**：**⌃⌥Space** を 1 回押す（または「音声送信を開始」をクリック）と、マイクがオンのままになります。もう一度押すと停止します。
2. **押している間だけ送信**：**Ctrl + Option を押したまま話し、離すと止まります**。キーを押している間だけマイクがオンになり、メインウインドウの「音声」が赤くなり、メニューバーのアイコンも赤くなります。離すとマイクはオフになり、このマシンの音量が下げられることもありません。初回は、このキーの組み合わせを検出するためにアクセシビリティの権限を求められます。オンになっていない場合はメインウインドウの「オプション」に案内が出るので、「オンにする…」をクリックしてください。
3. 押しているこのキーの組み合わせは、リモートデスクトップソフトによって作業する側のパソコンにも送られます。そのパソコンで音声入力や IME の音声ショートカットも Ctrl + Option に設定しておけば（[後述のヒント](#ヒントリモート接続では-fn-キーが届かないのでショートカットを変更する)を参照）、**1 回押すだけで「音声の送信」と「向こう側での音声入力の開始」を同時に行えます**。
4. どちらのショートカットも「設定… → ショートカット」で変更できます。

> 押している間、MicHop はこの Mac を一時的に消音します。リモートソフトが送り返してくる音がマイクに入ってエコーになるのを防ぐためで、キーを離して約 1 秒後に自動で元に戻ります。（「常に送信」では Apple のエコーキャンセルを使います。）

### ヒント：リモート接続では Fn キーが届かないので、ショートカットを変更する

UU Remote、Sunlogin、ToDesk などのリモートデスクトップソフトで接続しているとき、**手元の Mac で Fn キーを押しても、操作される側には届きません**。操作される側で macOS の音声入力を使っていても、WeChat Input Method の音声入力を使っていても、起動できません。理由は 2 つあります：Fn キーはまず手元の Mac に横取りされる（手元の Mac 自身で音声入力が始まってしまう）こと、そしてたとえリモートデスクトップソフトが転送したとしても、操作される側ではただの「擬似的なキー入力」にすぎず、システムや IME は通常それを受け付けないことです。

解決策：**操作される側**（例：Mac mini）で、音声入力のショートカットを変更します：

- **macOS の音声入力**：システム設定 → キーボード → 音声入力 → ショートカット →「カスタマイズ」。
- **WeChat Input Method**：WeChat Input Method の設定で、音声入力のショートカットを変更します。

**修飾キーの組み合わせ**がおすすめです。たとえば **左 Ctrl + Option**、または Ctrl とほかの修飾キー（Option、Shift、Command）の組み合わせです。

**Ctrl と数字キーや文字キーの組み合わせ（Ctrl+D など）は使わないでください**。音声入力は通常キーを押したまま話すので、文字や数字のキーを押し続けるとその文字が連続入力されてしまい、とても使いにくくなります。修飾キーだけの組み合わせなら、押し続けても文字は入力されません。

このテクニックは「音声を送信」モードと組み合わせて使います：操作される側の入力デバイスを MicHop Audio に設定し、リモートデスクトップ上で新しいショートカットを押したまま話せば、操作される側でそのまま音声入力できます。

## 同じネットワークにいない？ Tailscale を使う

1. 2 台とも [Tailscale](https://tailscale.com) をインストールし、同じアカウントでログインします。
2. Receiver のメインウインドウの「接続情報」にある「Tailscale」の行に 100.x.x.x と表示されるので、それを送信側の設定に入力します。Tailscale に表示されるマシン名を入力することもできます。
3. 「検出されません」と表示される場合は、まず Receiver 側のパソコンで Tailscale が接続済みか確認し、その行の更新ボタンをクリックして再検出します。それでも検出できない場合は、Receiver の「設定… → Tailscale → アドレスを手動設定」で、Tailscale のメニューに表示されているアドレスを入力してください。

Tailscale アドレスは自宅でも外出先でも使えます。同じ LAN 内にいるときは、自動的に直接接続されます。

## セキュリティ

- 各 Receiver にはランダムな 6 桁のパスコードがあり、パスコードが間違っているリクエストはすべて拒否されます。Receiver のメインウインドウの「パスコード」の行にある「新しくする」で変更できます（変更後は送信側で入力し直してください）。
- Receiver は TCP **8765**（テキスト）と **8766**（音声）の 2 つのポートで待ち受けており、通信は暗号化されません。自宅の LAN か Tailscale 内でのみ使用し、これらのポートをインターネットに公開しないでください。
- ペースト時にクリップボードを一時的に借用し、約 1 秒後に元の内容に戻します。

## よくある質問

- **接続できない**：2 台のパソコンが同じネットワークにあるか、両方とも Tailscale に接続されているか確認してください。LAN IP は変わることがあるので、ルーターで Receiver に固定 IP を割り当てるか、Tailscale アドレスを使うことをおすすめします。
- **アクセシビリティ権限がオフだと表示される**：アプリを再ビルドまたはアップデートすると、macOS が以前の許可を無効にすることがあります。アクセシビリティの一覧から古い項目を削除してから、もう一度追加してください。

## 自動アップデート

どちらのアプリも、自分で GitHub に新しいバージョンを確認しに行きます：起動から 30 秒後に 1 回、その後は 6 時間ごとに確認します。新しいバージョンが見つかると、自動でダウンロード・置き換え・再起動を行います。

- メインウインドウの左下で現在のバージョン番号を確認できます。「設定… → 一般」の「アップデートを確認」をクリックすれば、すぐに確認できます。
- 自動インストールしたくない場合は、「設定… → 一般」で「アップデートを自動でインストール」をオフにしてください。以降、新しいバージョンがあると設定に「x.y.z にアップデート」ボタンが表示され、メニューバーのメニューにも同じ項目が出ます。クリックしたときだけ更新されます。
- 使用中に邪魔をすることはありません：送信側は音声入力の小ウインドウが開いている間は更新しません。Receiver は音声受信中、またはテキストを受け取ってから 1 分以内は更新しません。
- 安全性：新しいバージョンは現在のバージョンと**同じ証明書**で署名されている必要があり、そうでなければインストールを拒否します。
- アップデート後も、アクセシビリティやマイクなどの権限は保持されるので、付与し直す必要はありません。
